Renderers read current page snapshots and registered actions. The server continues to control page identity, quantity ranges, quotes and transaction results.

## Pages, actions and lifecycle {#pages-actions-and-lifecycle}

`UiPage.key()` identifies the logical page; `UiPage.template()` selects theme configuration. Vanilla `menus` uses page IDs, while IA `pages` uses template IDs.

This list covers common flows and specialized pages. “Same” means the template equals the page ID. Always render actual current snapshots and registered actions.

### Market and publishing {#market-and-publishing}

| Page ID | Template ID | Main actions |
|---|---|---|
| `home` | Same | Trading categories, create/edit draft, player head, wallet, claims and my orders; disabled types are hidden |
| `profile` | Same | Interface, review queue, history, community, automation and permission-dependent risk/administration |
| `browse` | `browse` / `orders` | Search, filters, pagination, details and saved search; personal orders use `orders` |
| `browse-filters` | Same | Type, currency, material, sort, search and save current criteria |
| `order` | `detail` | Purchase, supply, bid, cancellation confirmation, favorite, seller and actual contents |
| `details` | Same | Long text and conditions |
| `editor` | Wizard templates below | Type, item/conditions, quantity, price and duration |
| `confirm` | `confirm` / `wizard-confirm` | Final confirmation and return |
| `preview` | Same | Inventory matching against the draft rule |
| `supply-preview` | `supply` | Protect slots, quantity, maximum, refresh and confirm |

Wizard templates follow the step: `wizard-type`, `wizard-item`, `wizard-terms` (buy order), `wizard-sale-terms`, `wizard-auction-terms`, then `wizard-confirm`.

### V1.1 additions

These specialized pages use their page IDs as template IDs and share `menus`, snapshots and action handling. Never guess keys, templates or button positions from display text.

#### Bundles, bulk listings and containers {#v11-bundle-and-bulk-pages}

| Page ID | Contents and main actions |
|---|---|
| `lot-editor` | Actual items, single/bundle/bulk mode, sale/auction, currency, price, duration and minimum/increment; contents and preview |
| `lot-select` | Actual inventory selection, refresh, selection summary and completion |
| `lot-contents` | Paginated read-only contents and further previews for verified containers |
| `lot-batch-plan` | Separate orders, per-order editing and individual confirmation |
| `lot-batch-item` | Actual item, sale unit price/auction total, minimum or increment |
| `lot-batch-results` | Individual results, pause reason and original operation; request the next manual confirmation |
| `container-preview` | Actual saved container contents, pagination, refresh and back; no extraction |
| `order-contents` | Published bundle entries and actual quantities, pagination, refresh and container preview |

Single items, mixed bundles and separate orders require distinct displays. Unpublished bulk plans persist only in the current session, without automatic continuation after restart.

#### Claim sources and current-page confirmation {#v11-claims-pages}

| Page ID | Contents and main actions |
|---|---|
| `claims-categories` | All sources and actual source categories |
| `claims-details` | Current-page selected assets, quantities and asset/order/operation references |
| `claims-confirm` | Current-page entries, quantities, inventory capacity and uncertainty notice; cancel or confirm |

The existing `assets` page uses source `46` for categories, `50` for select/clear current page, `51` for claim selected and `52` for details; `0..35` selects entries. Confirmation covers at most 36 current-page assets. Items that do not fit remain available; uncertainty, changed sessions or disconnects stop subsequent entries.

#### Business-item rules {#v11-business-rule-pages}

| Page ID | Contents and main actions |
|---|---|
| `rule-business` | Source/business ID, model, tags, exposed-field overview and admission notice |
| `rule-source` | Actual main-hand identity, vanilla source, clear identity or business ID only |
| `rule-model` | Minimum/maximum model values, import and separate bound removal |
| `rule-tags` | Paginated tags, collection input, main-hand import, remove or clear |
| `rule-fields` | Actual administrator-exposed fields and clear all |
| `rule-field` | Exact/contains, text input, main-hand scalar import and clear this field |

Validate each independent candidate before updating the draft. Fields come only from `items.exposed-fields`; OR and EXACT notices are read-only. Themes cannot add arbitrary scripts or rewrite actual matching values.

#### Community, notifications and sellers {#v11-community-pages}

| Page ID | Contents and main actions |
|---|---|
| `community` | Favorites, saved searches, notifications, subscriptions, seller, leaderboard, public prices and notification preference |
| `favorites` / `favorite` | Favorites pages, actual order/unavailable notice, open order/seller or remove |
| `saved-searches` / `subscriptions` | Saved-search and subscription pages, create |
| `saved-search` | Type, currency, material, text, source, category, price bounds, lot, display slot, sort, subscription, run, rename and delete |
| `saved-search-results` | Actual matching orders and pagination |
| `seller` | Seller statistics, their orders, currency and UTC calendar-day window |
| `leaderboard` | Same-currency rankings, UTC calendar-day window, metric and pagination |
| `notifications` / `notification` | Persistent notices, related orders and explicit mark-all-read; details update read status |

Chat delivery does not automatically mark notifications read. Sellers use 1/7/30 UTC calendar days; public prices use rolling 24-hour/7-day/30-day windows. Keep these distinct.

#### Prices and risk review {#v11-risk-pages}

| Page ID | Contents and main actions |
|---|---|
| `risk` | Local learning/capacity status, cases, prices, model and permitted manual training |
| `risk-cases` / `risk-case` | Case pages, buyer/seller audit, evidence, review history, status/notes and cloud confirmation |
| `risk-evidence` / `risk-review` | Paginated case evidence/review history |
| `risk-prices` / `risk-price` | Same-currency comparable items, rolling window and full comparison group |
| `risk-cloud-confirm` | Privacy/quota summary, send confirmation, cancel or shared in-progress/unconfirmed/existing-advice status |

Public prices require browse permission; other risk pages require audit permission, with administration additionally required for state, training and cloud writes. Case states do not punish players. Themes cannot resend in-progress or unknown requests.

#### Automation and income reservations {#v11-automation-pages}

| Page ID | Contents and main actions |
|---|---|
| `automation` / `automation-confirm` | Future-income withdrawals, login withdrawals, automatic claims, reservations and setting confirmation |
| `automation-income` | Actual reservation pages, refresh and release current-page releasable entries |
| `automation-income-detail` | Reservation status, withdrawal or release for `RESERVED` only; review notice for other states |
| `automation-income-confirm` / `automation-release-confirm` | Specific reservation/batch summary, cancel and confirm |

Disabling future-income withdrawals does not release existing reservations. Externally executing or unknown entries differ from ordinary available balances; preserve host status and pause notices.

#### Administration write tools {#v11-admin-tools-pages}

| Page ID | Contents and main actions |
|---|---|
| `admin-tools` / `admin-tools-player` | Target player, audit, ban/unban, cancellation, actual funds/assets, main-hand items, listing for a player and export |
| `admin-tools-orders` | Target player's orders, refresh, pagination and process current page |
| `admin-tools-money` / `admin-tools-assets` | Administrator's actual available wallets/assets and explicit transfer |
| `admin-tools-listing` | Actual sample, type, currency, price, quantity, duration, increment and preview |
| `admin-tools-export` / `admin-tools-retention` | Bounded export and retention of generated exports |
| `admin-tools-confirm` | Actual target, assets, reason and consequences for administrator confirmation |

Tools use actual existing money and items. Export retention removes only this network's expired generated exports, preserving financial records and unresolved operations.

## Home and profile slots {#home-and-profile-slots}

Default compact home source slots are `0` player head, `4` help, `8` claims, `20/22/24` trading categories, `31` create/edit draft, `45` wallet and `53` my orders.

`profile` uses `20` interface preferences, `22` review queue, `24` history, `29` community, `31` administration, `33` automation, `35` risk and `49` back. Administration/risk entrances depend on permissions. The review list reuses `history`.

Disabled `market.enabled-types` are hidden from home and publishing without rearranging source slots. Themes render only registered available actions and cannot re-enable modes.

Select home content with `gui.home-layout: auto|compact|legacy`; an existing `menus.home` preserves the legacy home under `auto`. See [vanilla GUI customization](/en/kitemarket/guide#customize-the-vanilla-gui) for migration.

Read current snapshots and actions instead of assuming all home layouts share one slot set.

## Quantities, amounts and results {#quantities-amounts-and-results}

Quantity maxima use actual wallet funds, available inventory items, policy and currency limits. The basic main-hand single-item auction uses that stack; multi-slot publishing reads the explicitly selected complete single lot, mixed bundle or independent groups. Transfers use actual balances and known backend receive capacity.

Changed quotes require another choice, and final submission rechecks limits; a theme must not raise them independently.

Receipts provide a separate “View / copy operation ID” action that sends the complete ID and copy control in chat. Summaries stay concise; `inspect` and the read-only API retain IDs.

### Transaction display {#transaction-display}

Single-item sales support partial purchases at a per-item unit price. Their per-order minimum defaults to 1 and can be set from 1 to the listed quantity; a remainder below the minimum must be bought together. Buy orders use unit prices for partial fulfillment. Both single and bundle auctions use whole-lot starting prices. Bundle sales use a whole-bundle price without partial purchase; bulk sales remain separate unit-price orders.

Render host amounts, input ranges, publication-time fees and item descriptions. Quantity, total and traded amounts are separate, with real item properties intact. Bundles also distinguish lot count, entry count and actual total item quantity.

Display timestamps and countdowns do not replace database deadline checks. Claims use actual item stack limits, leaving assets in claims when inventory space is insufficient.

Bundle `confirm` uses source `30` to confirm and `32` to cancel. Claims, automation and administration confirmations use `30` to cancel and `32` to confirm; `risk-cloud-confirm` uses `30` to send and `32` to cancel. Dispatch actual page tokens instead of assuming one slot always means confirmation.

## Actions and input {#actions-and-input}

The current `page.actions()` slot-to-opaque-token map is the action list. Entries without a token are informational. Never fabricate action strings or reuse a previous page's tokens.

Every open/update replaces identity, tokens and callbacks.

Input returns through `UiCallbacks.input(raw)` and closure through `closed()`. Returning `false` from `prompt()` retains the host's validated chat input and drafts.

## Provider lifecycle {#provider-lifecycle}

| Method | Lifecycle contract |
|---|---|
| `register(owner, provider)` | Enabled owning plugin; returns an idempotent unregister handle |
| `unavailable(...)` | Readiness only: `null` is ready, otherwise a reason code |
| `open(...)` / `update(...)` | Render cloned snapshots in the player context and replace all bindings |
| `refresh(...)` | Optional display update with the same identity and bindings; never reopen; default `false` |
| `isOpen(...)` / `close(...)` | Identify and close only your current view |
| `prompt(...)` | Native input, or `false` for host chat input |
| `changed(owner)` | Recheck after genuine resource changes; no trading authority |

Registration can wait for database initialization. If lookup is null, listen for `ServiceRegisterEvent`; discard old registrations and views when replaced. Unregister on owner disable; the host handles safe fallback.

Never manipulate player inventories from Folia's global thread. The example does not claim Folia certification.
