Use `menus` in `plugins/KiteMarket/config.yml` to customize home, market, publishing, condition, wallet, claims, community, automation and administration pages. Every page uses the same configuration mechanism, without a resource pack or IA.

Edit the file, run `/km reload`, then reopen the page. Reload validates a candidate first; invalid settings preserve the previous working configuration.

Appearance and placement do not change existing actions, permissions, trading rules or assets, and cannot add trading buttons.

See [interface and layout](/en/kitemarket/configuration/gui) for renderer and home settings.

## Titles, backgrounds, and controls

This example retains the legacy “My orders” source slot `32`, so it explicitly selects `home-layout: legacy`.

Merge it into the existing `gui` and `menus` sections without duplicating root keys. Omitted fields retain their defaults:

```yaml
gui:
  home-layout: legacy
menus:
  home:
    title:
      zh_CN: '&6交易集市'
      en_US: '&6Marketplace'
    background: BROWN_STAINED_GLASS_PANE
    buttons:
      '32':
        material: NAME_TAG
        name:
          zh_CN: '&6我的挂单'
          en_US: '&6My orders'
        lore:
          zh_CN:
            - '{default}'
            - '&8点击查看自己的订单。'
          en_US:
            - '{default}'
            - '&8View your own orders.'
```

### Configuration fields

| Field | Meaning |
|---|---|
| `menus.<page>.title` | Title string or a text map with `zh_CN`/`en_US` |
| `background` | Vanilla `Material` available on the current server; decorates only empty top/bottom slots in the new layout; `AIR` disables it |
| `buttons.<source-slot>.material` | Vanilla item icon for a functional control |
| `buttons.<source-slot>.name` | Control name as a string or bilingual text map |
| `buttons.<source-slot>.lore` | Additional market help as a text list or bilingual list map |
| `buttons.<source-slot>.slot` | That control's target slot |
| `slots`/`icons` | Existing placement/icon syntax; keys remain source slots |
| `switch.*` | Read for legacy compatibility; no automatic top-right interface switch is added |

## Source slots and placement swaps

Menu slots are `0..53`, excluding the player's inventory.

`buttons`, `slots` and `icons` use **source slots**, not the final visible position after the new layout remaps them. List sources `0..35` become physical `9..44`, so additional help for the first product uses `buttons.'0'`.

Legacy home source `32` is “My orders” and `34` is “History”; the compact home uses the [slot table in interface and layout](/en/kitemarket/configuration/gui#compact-home).

Placement changes must swap both sides rather than moving only one. This example explicitly retains the legacy home:

```yaml
gui:
  home-layout: legacy
  vanilla:
    layout: auto
menus:
  home:
    buttons:
      '32':
        slot: 34
      '34':
        slot: 32
```

`buttons.slot` and `slots` share one placement mechanism; do not configure a source twice. Existing syntax may instead use `slots: {'32': 34, '34': 32}`.

Custom placement requires `gui.vanilla.layout: auto` to select the compatibility layout, where source and physical slots match; do not simultaneously force `warm`.

### Existing home settings

Legacy `gui.home-slots` remains readable; migrate to the corresponding new home slots when choosing `compact`.

Existing `menus.<page>.switch` settings remain readable without injecting a button. Use the profile or `/km ui` to reach interface preferences.

## Text and default help

Titles and names accept a shared string or bilingual text map; Lore accepts a shared list or bilingual list map.

`&`/`§` support vanilla colors and formatting. Generated names default to gold and Lore to gray, with italics disabled unless explicitly requested.

`{default}` preserves original title/name text; a Lore line containing **only** `'{default}'` expands the default market help.

Omitting `lore` preserves help; `lore: []` clears only additional help.

`${field-name}` reads an existing read-only page field, such as `${wizard.step}`; missing fields display `—` without executing scripts.

Raw money fields use minor units, so prefer `{default}` to retain formatted amounts and asset destinations.

### Publishing policies and bundle fields {#v11-publishing-policy-fields}

`lot-editor` and `lot-batch-item` expose read-only publication bounds for the current player:

| Field | Meaning |
| --- | --- |
| `lot.policy.maximum-quantity` | Quantity limit for a complete single selection, each independent bulk group or one bundle lot |
| `lot.policy.minimum-price` | Current lower price bound in currency minor units |
| `lot.policy.maximum-price` | Upper price bound combining policy, currency limits and the selected quantity, in minor units |
| `lot.policy.maximum-duration` | Maximum duration in seconds; publication requires at least 60 seconds |

Single/bulk sales use a unit price; auctions/bundles use a lot total. Policy fields do not guarantee inventory quantity, space or final admission. Violations retain the draft, and each confirmation rechecks the original request without automatic repricing or minimum-quantity reduction.

Bundle confirmations also expose `lot.mode`, `lot.entries`, `lot.quantity` and `goods.quantity`: mode, entry count, number of lots and total item count. A bundle has one lot, which does not mean it contains only one item.

Preserve default confirmation help to show totals, fees, net income and asset destinations together. Do not recalculate published-order fees from current theme settings.

## Real products and assets

Functional controls may change material and name. Products, samples, selected inventory items and claim assets retain their actual material, name, enchantments and original Lore; `material`/`name` cannot disguise them as another item.

Only their placement and additional market help can change, without altering inventories, escrow snapshots or transaction subjects.

## All page IDs

These are the common pages; the groups below list the remaining configuration pages. Every key may be used in `menus`:

```text
home, profile, browse, browse-filters, order, details, editor, confirm, preview,
supply-preview, number, materials, durability, text-condition, enchantments,
enchantment-range, insufficient, wallet, wallet-currency, assets, history,
receipt, admin, admin-player, admin-wallet, admin-assets, admin-orders,
admin-player-history, resolve-source, doctor, inspect, evidence, ui, themes, result
```

Use page IDs rather than titles, translation keys or IA template aliases; for example, use `assets`/`confirm` for `claims`/`wizard-confirm`.

### Bundle, bulk and container pages {#v11-bundle-menu-ids}

```text
lot-editor, lot-select, lot-contents, lot-batch-plan, lot-batch-item,
lot-batch-results, container-preview, order-contents
```

`lot-editor` source `12` selects single/bundle/bulk mode, `14` selects sale/auction, and `32` opens a preview or bulk plan. Source `52` starts individual confirmation in the bulk plan and requests the next manual confirmation in results; neither completes the whole batch automatically.

Bundle `confirm` uses `22` for the summary, `24` for actual contents, `30` to confirm and `32` to cancel. `lot-contents`, `container-preview` and `order-contents` display real contents read-only.

### Business-item condition pages {#v11-business-menu-ids}

```text
rule-business, rule-source, rule-model, rule-tags, rule-fields, rule-field
```

Customize the business-rule overview, identity source, model range, tag collection, exposed-field list and individual-field editor. Business fields come only from `items.exposed-fields`. OR and exact-sample notices remain read-only; appearance settings do not grant arbitrary script editing.

### Community and notification pages {#v11-community-menu-ids}

```text
community, favorites, favorite, saved-searches, subscriptions, saved-search,
saved-search-results, seller, leaderboard, notifications, notification
```

Profile source `29` opens community. Favorites and search results retain real orders. The saved-search editor has separate currency, price-range, source, category, sorting and subscription controls. Seller day windows and price rolling windows retain their distinct server-provided descriptions.

### Price and risk pages {#v11-risk-menu-ids}

```text
risk, risk-cases, risk-case, risk-evidence, risk-review,
risk-prices, risk-price, risk-cloud-confirm
```

Public prices require browse permission; other risk pages require audit permission, with administration additionally required for state, training and cloud operations. In `risk-cloud-confirm`, source `30` sends the request and `32` cancels, unlike ordinary claim confirmation. Shared in-progress or unconfirmed requests expose no resend action.

### Automation and reservation pages {#v11-automation-menu-ids}

```text
automation, automation-confirm, automation-income, automation-income-detail,
automation-income-confirm, automation-release-confirm
```

Profile source `33` opens automation. `automation` uses `20/22/24` for future-income withdrawals, login withdrawals and automatic claims, and `40` for income reservations. Disabling future-income withdrawals does not release existing reservations. Confirmation uses `30` to cancel and `32` to confirm; review-required entries must not appear completed.

### Administration write-tool pages {#v11-admin-tools-menu-ids}

```text
admin-tools, admin-tools-player, admin-tools-orders, admin-tools-money,
admin-tools-assets, admin-tools-listing, admin-tools-export,
admin-tools-retention, admin-tools-confirm
```

Administration source `52` opens the permission-dependent tools. Money transfers, item transfers and listings on behalf of a player use actual existing assets. `admin-tools-confirm` shows the target, reason and consequences; `30` cancels and `32` confirms. Configuration cannot add punishment or asset-creation actions.

See [pages, actions and lifecycle](/en/kitemarket/ui-development/pages) for individual source slots and SDK action semantics.

## Validation and troubleshooting

Text entries are limited to 512 characters and Lore lists to 64 lines. Materials must exist on the current server.

Unknown settings, invalid slots and incomplete swaps invalidate a candidate; `command`, `action`, scripts and expressions are not style settings.

On failure, fix the field path identified by the response and logs. If changes are missing, reopen the page and check source slots, layout and whether a third-party theme uses its own template.

These settings do not install or download IA resources.

## v1.1: bundle and claims pages {#v1-1-bundle-and-claims}

### Claim categories and batch confirmation {#v11-claims-menu-controls}

Configure claims using actual page IDs and **source slots**:

| Page ID | Actual contents and controls |
| --- | --- |
| `order-contents` | `0..35` published bundle entries/quantities, `45/53` pages, `48` refresh, `49` back; verified containers open further read-only previews |
| `claims-categories` | `10` all sources, `19..28` source categories, `49` back |
| `claims-details` | `0..35` current-page selected assets/order/operation references, `49` back |
| `claims-confirm` | `22` batch/quantity/capacity/uncertainty notice, `30` cancel, `32` confirm, `49` back |

The existing `assets` page adds `46` categories, `50` select/clear the current page, `51` claim selected and `52` selected details. Sources `0..35` select current-page assets; `45/53` page, `48` refresh and `49` back. `claims` remains an IA template alias, not the `assets` page ID.

`order-contents`, `claims-details` and `assets` use list remapping; `claims-categories` and `claims-confirm` retain their source positions. Manual claiming processes only the confirmed current page, at most 36 entries. Items that do not fit remain available; uncertain outcomes or changed sessions stop subsequent entries.

List sources `0..35` default to physical `9..44`; tool sources `37/46/47/48/50/51/52` map to `5/0/1/7/2/3/4`. Non-list pages retain their source positions. SDK and IA snapshots already contain final physical slots; never remap them again.
