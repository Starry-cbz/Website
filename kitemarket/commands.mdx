主命令为 `/kitemarket`，别名 `/km` 和 `/market`，直接输入 `/km` 即可打开首页。交易命令会打开确认界面，不因输入命令立即成交。控制台支持本页单独列出的诊断命令。

`<...>` 为必填参数，`[...]` 为可选参数，不要把尖括号一起输入。币种填 `currencies` 下的 ID；订单/操作 ID 填完整 UUID。

默认首页将一口价、收购供货和竞拍分为三个入口；四角提供头像、领取箱、钱包和我的挂单。“发布 / 编辑草稿”直接进入向导，继续当前草稿；各类市场及“我的挂单”列表也保留该入口。已发布订单需撤单后重建。从头像进入“我的集市”，可查看自己的待核对操作、历史与界面偏好。旧自定义首页可继续保留，配置见[安装指南](/kitemarket/guide#原版-gui-个性化)。

## 玩家命令 {#玩家命令}

| 命令 | 用途 |
|---|---|
| `/km` | 打开主界面 |
| `/km help` | 帮助 |
| `/km ui [auto/vanilla/itemsadder] [theme-id]` | 保存同网络的后端与主题偏好，显示实际界面和回退原因；第三方界面不需要自家 DLC |
| `/km browse [BUY/SELL/AUCTION]` 或 `/km market [...]` | 浏览收购、一口价或竞拍；省略类型浏览全部，菜单支持搜索和分页 |
| `/km wallet` | 查看各币种可用与冻结余额，进入充提 |
| `/km claims` 或 `/km assets` | 领取箱 |
| `/km history [all]` | 查看自己的历史；`all` 需要全局只读审计或管理权限 |
| `/km orders` 或 `/km mine` | 查看自己的订单 |
| `/km create` 或 `/km rule` | 编辑本次挂单与物品条件 |
| `/km preview` | 检查背包中哪些物品符合当前条件 |
| `/km cancelinput` | 取消聊天输入并返回原页面，保留草稿与选择 |
| `/km order <订单ID>` | 打开指定订单 |
| `/km cancel <订单ID>` | 打开撤单确认；他人的未完成订单需要管理权限及原因 |
| `/km inspect <操作ID>` | 查看自己的操作和结构化证据；全局审计者或管理者可核查他人的操作 |
| `/km deposit <币种> <金额>` | 外部经济转入市场钱包，需位于对应网关 |
| `/km withdraw <币种> <金额>` | 市场钱包转回外部经济，需位于对应网关 |
| `/km buy <订单ID> [数量]` | 按单价购买指定数量，遵守该订单最低购买量 |
| `/km supply <订单ID> <数量>` | 向收购单供货 |
| `/km bid <订单ID> <金额>` | 对整份拍卖提交总出价 |
| `/km sell <币种> <每件单价> <数量> [秒数] [最低购买量]` | 托管与主手样品匹配的物品，创建一口价订单 |
| `/km request <币种> <单价> <数量> [秒数]` | 使用当前草稿条件创建收购单 |
| `/km auction <币种> <起拍总价> <数量> [秒数] [最小加价]` | 将主手物品作为一份拍卖 |

有效期单位为秒，最短 60 秒，最长受 `market.maximum-duration-seconds` 限制。创建命令会沿用当前 GUI 草稿中未重新指定的参数；发布前检查确认页。收购建议先 `/km create` 设置并预览条件。也可从自己的订单详情撤单；有有效出价的拍卖不能由卖家撤销。

一口价金额是每件单价，本次总额为单价×购买数量。最低购买量在出售发布条款页设置，默认1，可设为1至发布数量；当余量不足最低量时，只允许买完全部余量。建议购买时填写数量，或从订单详情打开数量页，核对金额后确认。收购也是单价，竞拍起价与出价则为整标总价。

也可在出售命令的秒数之后填写最低购买量，例如 `/km sell points 8 16 86400 3` 表示单价8、数量16、有效期86400秒、最低购买3件。出售的最后一个参数与拍卖的最低加价含义不同。

## v1.1 候选入口

以下命令属于 [v1.1 候选实现](/kitemarket/v1-1/overview)，不是 v1.0 已发布构件的新增命令声明。它们打开真实页面，仍检查基础 `kitemarket.use`、对应功能权限和会话。

| 命令 | 用途与权限 |
| --- | --- |
| `/km community` | 收藏、保存搜索、订阅、通知、卖家与排行 |
| `/km prices` | 公开价格参考，需要 `kitemarket.browse`；不会开放管理案件 |
| `/km automation` | 个人自动化设置与收益预约，需要 `kitemarket.wallet` |
| `/km lots` | 单品、整包和独立批量上架，需要 `kitemarket.create`；每单仍确认 |
| `/km risk` | 学习状态、案件、证据和复核记录，需要 `kitemarket.audit.all`；写入另需管理权限 |
| `/km tools` | 管理封禁、撤单、资金/实物操作、导出和保留策略，需要 `kitemarket.manage` |

社区页提供公开价格入口。自动化默认关闭，管理资金/实物操作使用已有真实资产，风险及云端建议不自动执行处罚。具体行为见候选专题。

## 条件编辑输入 {#条件编辑输入}

编辑器通过菜单选择材料、附魔和范围；需要精调数值或填写文本时再输入聊天。输入 `cancel` 或运行 `/km cancelinput` 取消聊天输入。

| 字段 | 示例 |
|---|---|
| 材料 | 目录多选；批量输入如 `DIAMOND_SWORD,NETHERITE_SWORD` |
| 附魔 | 按中文名、英文名或 ID 搜索，选择后用最低／最高等级按钮，或从主手导入 |
| 剩余耐久 | 百分比范围按钮、预设或单个整数精调 |
| 名称 | 菜单选择精确／包含，聊天只输入文本，如 `矿工镐` |
| Lore | 同名称；输入字面 `\n` 表示换行，所有行合并后比较 |

名称和 Lore 不需要 `=`、`~` 前缀；清空和主手导入均有独立按钮。完整规则见[交易条件](/kitemarket/trading)。

结果消息提供查看详情入口，收据中的“查看／复制操作编号”可按需显示完整 UUID 并复制；需要输入 `/km inspect` 时使用该编号。默认摘要不逐条展示长编号，操作记录与审计查询仍可追溯。

## 管理员命令 {#管理员命令}

| 命令 | 用途 |
|---|---|
| `/km admin` | 查看待核对操作；只读审计者只能查看证据，管理者可以进入核对流程 |
| `/km admin <玩家UUID或在线名>` | 查看指定玩家的钱包、全部资产状态、订单和历史；支持离线 UUID，名字只解析本服在线玩家 |
| `/km doctor` | 查看数据库初始化、网络、许可、节点和 provider 准入状态；支持只读审计权限 |
| `/km doctor items` | 在实际服务器执行物品规则/序列化诊断，逐样本结果写入日志；不改变玩家资产 |
| `/km license` | 请求下一轮维护立即刷新许可；不是绕过验证或延长到期 |
| `/km license reactivate` | 确认后重新激活已签名确认 `UNBOUND` 的同一网络与同一许可证 |
| `/km inspect <操作ID>` | 核查节点、执行阶段、金额与物品摘要，并查看该操作的管理修复前后证据 |
| `/km cancel <订单ID>` | 强制取消未完成订单，必须输入至少 5 个字符的原因并确认 |
| `/km resolve <操作ID> <SUCCEEDED/FAILED> <原因>` | 核实外部结果后登记成功/失败，仍需界面确认 |
| `/km reload` | 校验并更新语言、界面布局/图标与新单费率 |

核对原因至少 5 个字符，并应具体描述证据。不要为了清空列表随便选择结果；后果见[运维指南](/kitemarket/operations)。管理员可在订单详情撤销订单，但仍留下审计记录。

第三方 IA 主题使用配置文件、自己的资源和 `/km reload`，不需要额外的 KiteMC 主题授权。安装步骤见[ItemsAdder 接入](/kitemarket/dlc)。

玩家审计入口固定查询指定 UUID；资产页可筛选待领、托管、交付中、已领和已消耗状态，并分页查看。它不会替该玩家领取、充提或改余额。`inspect` 的 `PREPARED` 只能查看和刷新，只有 `UNKNOWN` 才能进入管理核对；未结束的外部调用仍会阻止登记结果。

| 权限 | 默认值 | 范围 |
|---|---|---|
| `kitemarket.use` | 所有玩家 | 玩家命令的基础入口 |
| `kitemarket.browse` | 所有玩家 | 浏览与查看公开订单 |
| `kitemarket.create` | 所有玩家 | 草稿、规则预览、发布与撤销自己的订单 |
| `kitemarket.trade` | 所有玩家 | 购买、供货、竞价 |
| `kitemarket.wallet` | 所有玩家 | 钱包、充提与自己的物品领取 |
| `kitemarket.audit` | 所有玩家 | 查看自己的历史和操作 |
| `kitemarket.audit.all` | OP | 玩家钱包/资产/订单审计、全局历史、他人操作、待核对列表与诊断，只读 |
| `kitemarket.manage` | OP | 管理写操作、诊断、授权刷新与重载 |
| `kitemarket.admin` | OP | 兼容管理权限，包含 `kitemarket.manage` 和 `kitemarket.audit.all` |

基础入口和对应功能权限需要同时具备。只授予 `kitemarket.audit.all` 可进行全局只读审计，不能强制撤单、核对登记、刷新授权或重载。`kitemarket.manage` 也允许上述审计查询。没有 `/km pay` 或任意改余额命令。

## 控制台与重载 {#控制台与重载}

服务器控制台及 RCON 支持 `km doctor`、`km doctor items`、`km license`、`km inspect <操作ID>`、`km reload`。同网同许可证的显式重新激活使用 `km license reactivate confirm`；普通 `km license` 仅刷新，不自动重新绑定。控制台不执行发布、成交、领取、充提或人工结果登记。

物品诊断构造本地样本并检查指纹、数量、元数据和规则原因，容器样本明确排除；它不会创建世界方块或物品资产。结果只证明当前服务器的诊断样本，不自动取得交易、经济后端或整个版本矩阵的认证。

`/km reload` 是 KiteMarket 的配置校验入口，不是服务端 `/reload`。它只更新显示配置和新单费率；无效语言、图标、槽位或费率不会替换当前有效设置。`network`、`database`、`currencies`、`license` 及订单数量/时长限制的变更要求完整重启。bStats 开关也在重启后生效。具体示例见[安装与配置](/kitemarket/guide)。
