三种交易都使用市场钱包和托管资产。确认页的数据可能在其他节点变化，最终以服务端重新校验的订单版本、价格和剩余数量为准。页面过期时重新查看，不要凭旧截图确认付款。

点击 `/km` 首页的“发布 / 编辑草稿”，即可直接打开向导并继续当前草稿。各类市场及“我的挂单”列表也保留该入口。返回、刷新或切换界面保留未发布的条件；已发布订单需先撤单再重建，不能原地修改。

出售／拍卖发布、购买和出价确认页展示真实标的的名称、附魔与 Lore；精确样品收购也展示保存的样品。数量、总价、冻结金额及税费以确认说明为准，展示物品不会参与实际扣物或结算。

### 发布数量与最大值 {#发布数量与最大值}

发布向导的“最大值”按当前实际可用量计算：

| 类型 | 数量上限 |
|---|---|
| 收购 | 配置数量上限、币种金额上限÷单价、市场钱包可用余额÷单价，取最小整数 |
| 一口价 | 配置数量上限、币种金额上限÷单价、背包中与主手样品属性完全一致的真实数量，取最小值 |
| 竞拍 | 配置数量上限与当前主手这一堆数量，取最小值；起拍价为整标总价 |

外部经济余额不会自动计入收购预算。钱包不足时可进入充值，返回后保留草稿；出售或拍卖没有可用物品时显示不足。应用数量和发布确认都会重新检查，余额或物品减少时需重新选择，GUI 报价不预占之后的交易能力。供货的“最多可交”另按订单剩余需求与本次选中的匹配物品计算。

## 高级收购 {#高级收购}

买家先确定币种、单价、数量、有效期和物品条件，再冻结订单需要的市场资金。卖家选定符合条件的物品和交货数量，确认后才提交。订单允许部分供货；取消或到期后返还未成交部分的资金。

收购条件提供三种模式。**普通材料**只接收所选原版材料且没有附带元数据的物品，不会悄悄收进命名、附魔或自定义物品。**高级条件**只检查明确设置的规则。**精确样品**比较完整物品指纹，忽略数量。

高级条件采用 **AND**：设置了材料、附魔、耐久和名称时，交货物品必须同时满足它们。材料集合内部任选一种即可。额外附魔默认禁止，需要在编辑器中明确开启；名称/Lore 只有精确和包含两种匹配，不接受正则表达式。

| 条件 | 含义 |
|---|---|
| 材料 | 从所选材料集合中匹配一种；与其他条件同时生效 |
| 附魔 | 每个指定附魔必须落在自己的等级区间；额外附魔是否允许单独控制 |
| 耐久 | 剩余耐久百分比，0–100；例如 80–100 表示至少保留 80% 耐久；设置后拒绝没有耐久属性的物品 |
| 名称 / Lore | 根据编辑器指定的精确或包含规则匹配；未设置的字段不增加限制 |
| 精确样品 | 匹配数量归一后的真实物品指纹；交易数量独立计算 |

原版高级条件只检查编辑器明确支持的属性。已通过物品准入、但高级条件无法解释的自定义数据需使用精确样品；精确模式不解除下文的物品准入限制。

### 条件编辑 {#条件编辑}

订单详情和发布确认页会按当前模式说明真正生效的条件。普通材料模式不叠加编辑器里保留的高级条件；高级条件模式显示各项规则；精确样品模式按完整样品属性匹配。

点击「材料集合」从当前服务端的物品列表多选，点击已选项即可移除。可按材料 ID 筛选、只查看已选材料、加入主手材料，或批量输入 ID；最多 64 种。未通过物品准入的材料不能新增选择。无效批量输入保留原集合，清空集合后需要重新选材才能发布。

点击「附魔」打开选择器，可按中文名、英文名或 ID 搜索，例如 `锋利`、`Sharpness`、`minecraft:sharpness`；也可清空搜索。取消输入保留原筛选和草稿。再点击某个附魔，通过最低、最高等级按钮设置区间，也可移除单项条件。最低等级为 0 表示允许没有该附魔，范围 `0–0` 表示要求没有该附魔。「从主手导入」会用手中物品的附魔替换当前附魔条件，并把各项最低、最高等级设为手中等级；尚未选择材料时，同时补入主手物品的材料。其他已编辑条件保留，导入后切换为高级条件模式。

「耐久」提供最低、最高百分比按钮，每次调整 5%；点击数值可精调一个整数，也可选择 100%、至少 50% 或导入主手的剩余耐久。设置范围会要求物品具有耐久属性；清空则不限制耐久。

名称和 Lore 在独立页面选择「精确」或「包含」，聊天只输入内容，无需 `=`、`~` 条件前缀。Lore 多行用 `\n` 连接。主手导入使用物品的完整原文本，包括格式和换行，适合保留颜色格式的精确匹配。清空表示不限制；导入空文本并精确匹配则要求该字段为空。

### 供货预览 {#供货预览}

1. 在收购订单详情点击「供货」，进入背包存储格预览。物品图标保留真实名称、附魔和原始 Lore，并追加是否匹配、不匹配原因、本次扣取和保留数量。
2. 点击符合条件的物品格，可以保护该格；再次点击取消保护。受保护物品不参与本次供货。保护仅属于本次预览流程，不是永久背包设置，重新进入供货时需重新选择。
3. 设置交货数量，或点击「最多可交」按当前未保护的匹配物品和订单余量重新计算。系统按背包格顺序选择物品；数量不足时显示缺口，不能进入最终确认。点击「刷新」重新读取订单和背包，查看最新余量。
4. 查看每格的扣取数量，以及本次成交总额、税额和净收入。确认页继续列出供货来源格和数量，便于发现误选的工具或收藏品。
5. 最终确认后，扣物前再次检查实际背包的属性和数量，订单提交时重新检查订单版本和余量。背包变化会拒绝扣取；订单过期或被其他玩家供满时，按操作记录处理已托管物品，先查看领取箱再发起新操作。

预览不会移动或修改背包物品。交易转移本次选中的真实物品快照，不会根据采购样品重新生成物品。

## 精确样品与自定义物品 {#精确样品与自定义物品}

精确模式保存物品序列化数据，比较名称、Lore、附魔及可保存的自定义数据等完整属性。样品数量不构成价格或数量限制。同一物品发生耐久、名称或其他元数据变化后，可能不再匹配。

新建的精确收购单同时保存实际样品与规则指纹，发布时检查准入、材料和指纹一致，样品数量归一为 1。样品用于订单展示；供货仍转移供应者的真实物品。历史仅保存指纹的订单明确缺少展示样品，不根据指纹猜测或重造原物品。

KiteMarket 不解析第三方物品 ID，也不承诺两个外观相同物品等价。所有节点的 Minecraft 版本和物品配置必须一致。先用目标插件生成的真实样品验证，再开放给玩家。

精确样品仍须通过物品准入和序列化往返保真检查，不能用来绕过限制。`1.0.0` 不开放潜影盒、收纳袋等具有嵌套存储结构的物品的新交易，空潜影盒也不在支持范围；其他特殊物品或数据只有通过当前构件的准入检查后才能交易。看到 `UNVERIFIED_SPECIAL_ITEM`、`UNVERIFIED_ITEM_DATA` 或 `ITEM_ROUNDTRIP_UNSAFE` 时，应停止发布该物品，而不是切换精确模式重试。已有托管资产的安全退出按[故障与迁移说明](/kitemarket/operations)处理。

## 一口价 {#一口价}

卖家托管与主手样品属性相同的真实物品，设置**每件单价**和有效期。一个订单不能混入不同属性的物品，买家可选择数量部分购买。例如单价8，购买16个的总额为128。买家查看单价、数量、币种与本次总额，再确认购买。成交物品进入买家的领取箱，卖家取得扣除订单税费后的市场收入；未售物品可撤回领取箱。背包已满不会把物品强制丢到地上。

出售发布条款页可设置**最低购买量**，默认1，范围为1至发布数量。每次购买须达到最低量；如果余量已经少于最低量，则只允许一次买完全部余量。例如最低3、剩余2时可买2，不能只买1。该条件发布后固定，修改需撤单重建。

发布确认页按一次售完全部数量估算成交总额、税额和净收入；分批购买各自计算税额，累计净收入可能存在最小货币单位的舍入差异，以单笔记录为准。收购按单价分批供货，竞拍按整标总价出价。

市场列表与订单详情保留实际样品的名称、附魔和原 Lore，其后分段追加商品信息与购买、供货或竞拍提示。剩余数量单独显示，详情另列总量与已成交数量，不使用剩余／总量分数。角标仅在物品原生堆叠允许范围内（最多99）显示真实数量，超出时使用单图标，精确数量始终以 Lore 为准，不改变真实物品的堆叠限制。

商品信息显示上架、到期和剩余时间。中文日期为 `yyyy年MM月dd日 HH:mm:ss`，英文为 `yyyy-MM-dd HH:mm:ss`，采用服务器时区。剩余至少一小时显示整小时，至少一分钟显示整分钟，不足一分钟显示秒；页面倒计时不会改变数据库的截止或结算规则。数量和成交金额以订单说明与确认页为准，展示图标不会成为结算时新生成的物品。

## 公开竞拍 {#公开竞拍}

玩家手动提交整件或整堆拍卖的总出价，最高有效出价全额冻结市场资金，被超价后立即释放回钱包。不存在自动代理最高出价、买断或隐藏保留价。在剩余不足 30 秒时接受有效出价，会将截止延至至少该次出价后 30 秒，总延长不超过原截止后的 5 分钟；这些值是固定规则，截止以数据库时间判断。

起拍价、最小加价和结束时间以订单为准。不能给自己的订单出价。已经存在有效出价的拍卖不应通过普通卖家撤单绕过结算；管理员干预需要审计原因。

起拍价是整个拍卖标的的总价，不乘以物品数量。发布确认页的税额和净收入按起拍价预估，最终使用成交时的最高有效出价结算。

详情显示最低有效出价、最低加价、你是否领先，以及按最低价出价还需追加冻结的金额。领先者再次加价仅需补足差额。「按当前最低价出价」会先打开确认页；也可以输入更高总价。其它玩家出价改变订单版本后，旧确认会被拒绝，需要刷新；不会自动追价。最低有效价超过币种上限时不能再加价，已有最高价仍按规则结算。

到期后物品进入胜出者领取箱，税后收入进入卖家钱包；无人出价则将物品退回卖家领取箱。三种交易均禁止自己购买、供货或竞拍。发布后的价格、条件和费率不能直接改写，修改需撤单重建；管理员不能直接撤销已经完成的成交。

## 托管与领取 {#托管与领取}

物品进入托管后，即使发单失败，也应先检查领取区与操作记录，不能直接再次扣取。领取按真实物品自身的堆叠上限拆分，GUI 角标不会放宽这个上限。空间不足时物品仍留在领取箱，并提示先腾出空间再领，不掉落或删除。余额或物品结果显示 `UNKNOWN` 时停止重试并记录操作 ID，交由管理员[核对](/kitemarket/operations)。

## 搜索与交易收据 {#搜索与交易收据}

列表可以按交易类型、币种、材料筛选，按即将到期、最新发布或价格排序。搜索支持订单编号、材料 ID、真实名称、Lore 和生效的高级条件文本；`%`、`_` 是普通文字，搜索不检查物品字节或指纹。筛选在数据库分页前执行，翻页保留条件。价格排序使用一口价与收购的每件单价、拍卖当前最高价（无出价时为起拍价）。请先筛选同一类型、同一币种；不进行兑换或跨币种估值。

点击历史记录打开只读收据，可查看单笔成交数量、币种、总额、该单固定税额、税后收入归属，以及可确认的退款或退物。卖家收款按关联成交操作计算，不使用订单累计数量推测单笔收入；自己的收款收据不提供买家的原始操作证据。

竞拍者自己的历史包含被超价时释放的冻结金额，以及胜出后的整标结算记录。自己追加出价不会被记作「被超价」；重复提交或多个节点同时结束不会重复生成这些记录。

历史当时状态与当前操作状态分别显示。旧记录缺少资料时明确标注，不把缺失金额当成 0 或成功。提交后的结果区分成功、失败与待核对，并提供查看详情及适用的钱包／领取箱入口。需要编号时，在收据点击“查看／复制操作编号”，即可在聊天查看完整 UUID 并复制用于 `inspect`；默认摘要保持简短，审计记录仍保留编号。待核对不会提供自动重放、退款或补发。
