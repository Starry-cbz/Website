一个网络使用共享数据库中持久化的网络 UUID，不按子服端口收费。复制配置去创建另一套独立数据库不能使它自动成为同一授权网络。正式配置包含正确的产品 ID、端点和生产签名公钥，服主填写自己的许可证即可；公钥不是许可证密钥。

## 刷新、离线与到期 {#刷新、离线与到期}

| 情况 | 行为 |
|---|---|
| 首次使用 | 必须联网成功验证；无成功凭据时没有离线宽限 |
| 正常运行 | 成功验证后每 6 小时刷新 |
| 授权服务暂时不可达 | 使用有效签名凭据，最多至最后一次成功验证后 7 天 |
| 商业到期早于离线期限 | 以商业到期时间为准，不额外赠送 7 天 |
| 明确撤销、绑定不符或签名失败 | 不能当作普通网络中断放行 |

授权失效后停止新增交易并进行受控清退。查询、合法取消、资产领取和受支持的提现退出不能因商业失效被无条件封死。数据库、物品领取区和历史记录不会为此删除。

单个节点的配置、签名或绑定校验错误只阻止该节点取得交易许可，不据此清退其他正常节点；全网清退依赖有效签名状态或已保存凭据的有效期耗尽。

## 同网同许可证重新激活 {#同网同许可证重新激活}

已保存并验证的签名状态为 `UNBOUND` 时，具有管理权限的玩家可运行 `/km license reactivate`，在界面确认后重新激活。控制台／RCON 使用 `km license reactivate confirm`；普通 `/km license` 只刷新，重启或重连也不会自动抢占旧绑定。

此入口只恢复原网络 UUID 与原许可证，要求配置中保留该许可证的有效密钥。服务端和客户端均核对原许可证身份，不把换成另一把密钥当成同网恢复。`REVOKED`、`SUSPENDED` 或商业到期不是这一入口的可恢复状态；需要变更许可证或网络归属时，仍走许可证中心的显式管理流程。

重新激活保留网络、钱包、领取资产和历史。必须收到有效的新签名授权才重新开放交易；已清退的订单不会复活。网络请求失败或响应不确定时先检查授权状态，不删除绑定、token 或数据库记录来反复激活。

## 网络身份与迁移 {#网络身份与迁移}

网络 ID、绑定信息和随机网络 token 必须持久化并由各节点共享。不要为了重试激活而手动删除它们，也不要给每个节点生成一个新网络。

迁移时先停止旧节点写入，再备份并恢复完整数据库和对应配置。保留网络身份；需要转移许可证时使用许可证中心的正式流程。不能只复制 JAR，也不能通过改绑定字段“修复”授权。

管理员应保持系统时钟准确，配置正确的授权端点和可信公钥。不要把私钥、完整许可证密钥或网络 token 发到聊天、工单截图或公开日志。

[安装配置](/kitemarket/guide)提供实际字段；[故障处理](/kitemarket/operations)说明清退与未确定操作。

## 界面与第三方主题 {#界面与第三方主题}

原版 GUI、ItemsAdder v4 适配、配置主题和 Java SDK 属于基础能力。第三方可自由开发、自用、分发或独立销售自己的主题，无需额外的 KiteMC 主题授权。各主题资源遵循其作者的许可，第三方插件和资源不包含在 KiteMarket 售价中。

主题不可用时回退原版，不改变市场钱包、物品或授权状态。主许可证仍按上文管理市场本身。安装见[ItemsAdder 接入](/kitemarket/dlc)，开发见[界面 SDK](/kitemarket/ui-development)。
