## 精确匹配 {#精确样品与自定义物品}

精确模式保存物品序列化数据，比较名称、Lore、附魔及可保存的自定义数据等完整属性。

样品数量不构成价格或数量限制。同一物品发生耐久、名称或其他元数据变化后，可能不再匹配。

## 样品保存与展示

新建的精确收购单同时保存实际样品与规则指纹，发布时检查准入、材料和指纹一致，样品数量归一为 1。

样品用于订单展示；供货仍转移供应者的真实物品。

历史仅保存指纹的订单明确缺少展示样品，不根据指纹猜测或重造原物品。

## 自定义物品与节点一致性

外观相同不代表物品等价。名称、Lore、耐久、附魔、自定义数据和业务身份都可能影响匹配或完整属性比较。

所有节点的 Minecraft 版本和物品配置必须一致。先用目标插件生成的真实样品验证，再开放给玩家。

### 公共 API 业务身份桥接 {#v11-item-identity-bridges}

启用对应插件后，可通过 ItemsAdder、Oraxen、Nexo、MMOItems 的公共 API 读取真实业务来源与 ID，用于高级收购和筛选。读取失败或身份未确认时，不从外观、名称、Lore 或猜测 NBT 补造 ID。

业务身份只增加明确的语义条件，不放宽托管保真、完整 EXACT 比较或其他已设置规则。无法由已确认身份安全限定的未知数据，继续使用完整精确样品。

高级编辑还支持 CustomModelData 范围、最多32个必须存在的 PDC 键名，以及 `items.exposed-fields` 开放的字符串、数字和布尔字段。设置方式见[业务身份与开放字段](/kitemarket/trading/buy-orders#v11-business-identity-and-fields)。

<Note>
公开 API 桥接不代表所有物品组合都已认证。目前固定验证组合为 Paper 1.21.11、Java 21、Oraxen 1.220.0：一个实际自定义镐完成身份读取、名称搜索、上架、购买与领取，原生属性与堆叠量一致。此结果不覆盖全部 Oraxen 物品或资源包外观；Nexo、MMOItems/MythicLib 的完整运行组合尚未认证。
</Note>

## 物品准入

精确样品仍须通过物品准入和序列化往返保真检查，不能用来绕过限制。

特殊物品和嵌套数据只有通过当前构件的准入检查后才能交易。物品来源插件、SDK 或界面主题不能代替准入结论。

看到 `UNVERIFIED_SPECIAL_ITEM`、`UNVERIFIED_ITEM_DATA` 或 `ITEM_ROUNDTRIP_UNSAFE` 时，应停止发布该物品，而不是切换精确模式重试。

### 只读容器预览与往返保真 {#v11-container-preview-and-fidelity}

已通过准入的容器可以在订单内容页打开只读预览，展示实际保存的内部物品。点击预览不能取出物品，也不会改变容器内容。

容器本身及内部每一项都要经过保存、还原和完整属性比较。嵌套或结构超过支持范围、损坏快照或属性无法完整往返时拒绝发布，不替换为空容器，也不删除不认识的内容来强行通过。

成交、撤回或到期后的实际物品进入领取箱。背包不足时继续待领，物品数量与原生堆叠规则保持不变。
