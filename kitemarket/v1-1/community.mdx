本页属于 [v1.1 候选专题](/kitemarket/v1-1/overview)。个人资料和通知持久保存，统计只使用已观察的已提交成交。

## 收藏与保存搜索

在订单页收藏，再从社区页管理；每人最多256个收藏和20个保存搜索。订单不可用时仍可移除收藏，不把它伪装成有效商品。

保存搜索记录类型、币种、材料、可读文字、业务来源、分类、价格区间、单品/整包、展示位和排序。运行搜索读取当前真实订单，不把保存时结果固定为可买库存。

材料名称匹配与主市场一致。例如保存“钻石”后，运行和订阅仍能匹配没有精确样品的钻石收购单；编辑文字会更新材料匹配，保留其他筛选条件。

名称搜索包含去除颜色码后的可读文字，逐字渐变不会拆开关键词。现代物品没有自定义显示名时使用公开 API 的 `item_name`，自定义显示名优先。搜索名称不代替业务 ID 或完整物品属性比较。

价格区间输入为非负整数最小货币单位。两位小数币种中 `123` 表示1.23；不同币种的相同整数不表示同等购买力。

订阅开关决定是否接收后续新匹配订单。修改条件先保存有效候选，不会替玩家自动购买、供货或出价。

收藏/订阅发现索引最多1024人。索引满时新增收藏或订阅明确拒绝，不留下半保存的偏好；未订阅的手动保存搜索仍可使用。

## 个人通知

通知包括新匹配订单、收藏终态、购买/售出成交及拍卖被超价。同类型事件按一分钟合并，重放去重，最多保留100条。

通知在市场网络中持久保存，离线不会因聊天没送达而丢失。关闭个人通知只影响后续通知，不删除原有收件箱或资产记录。

登录提示真实未读数量，在线每15秒最多合并一条聊天提醒。同一分钟通知继续增加时提示增长，不逐笔刷屏。

提醒不自动标为已读；打开详情或明确“全部已读”才更新持久状态。聊天只展示少量短订单引用，完整目标在详情页。失败读取不会冒充零未读。

## 公开广播和 Discord

两者默认关闭，管理员自行启用。

公开游戏广播按节点独立消费新订单，60秒汇总，按币种与订单类型分组。不比较或相加不同币种的金额，也不插入任意物品名称/Lore。

Discord 为真实订单保存消息身份：创建消息，余量或最高竞价变化时更新同一条消息，订单终态删除。网络限频和每日额度合并重复变化，`allowed_mentions` 关闭提及。

摘要使用本地化的类型、材料和币种名称，金额按币种精度显示。单价、整包总价、起拍总价和当前竞价总额分别标注；整包展示实际物品总数，拍卖展示整件数量。无样品收购只列公开材料和条件模式，具体条件在游戏内查看。

消息保留订单假名，不发送玩家身份或原物品名称/Lore/NBT，不提供交易执行按钮。

`notifications.discord.language` 支持 `zh_CN`、`en_US` 和默认的 `auto`。`auto` 继承服务器 `language`；服务器也是 `auto` 时使用中文。币种名称读取所选语言的 `display-name`，文案在 `lang/community_<语言>.yml` 的 `community.discord` 下配置。

Discord 配置与展示快照在启动时固定。修改后正常重启服务器，`/km reload` 不更新这部分配置。

创建请求超时、服务端错误或无法确认消息 ID 时保留 UNKNOWN，不自动重复创建；明确被限流拒绝才按等待时间重试。消息发送失败不回滚已完成游戏成交。

## 卖家与排行榜

卖家资料、排行按卖家与币种独立累计已提交成交，可选择1、7、30个 **UTC 日历日**。这是包含当天的日桶窗口，不是精确滚动24、168或720小时。

均价、成交量与净收入来自实际观察，读取失败或没有观察数据会明确区分。切换币种只改变统计范围，不生成跨币种汇率或把金额混排。

排行榜可按净收入、成交笔数或已售数量切换。点击卖家进入其统计与订单页；卖家订单页也包含已完成订单，历史数量不是当前库存，能否交易以订单状态为准。

卖家索引最多1024人。超过索引容量后个人精确成交统计继续保存，完整排行榜明确不可用，不把已索引的一部分卖家展示为全网络排行。

## 公开价格参考

价格参考按同币种及完整可比物品分组，提供滚动24小时、7天、30天窗口。

| 数值 | 含义 |
| --- | --- |
| 中位数 | 成交单位价的中位数 |
| 均价 | 以实际成交数量加权的单位价 |
| 成交量 | 窗口内真实已提交数量和成交记录 |

不同属性的稀有物品、不同整包组合或币种不能强行合并。无可比基线显示缺少数据，不把零作为估值。参考价不是保证成交的报价，也不是作弊结论。

风险规则如何使用参考数据见[管理与风险复核](/kitemarket/v1-1/administration-risk)。
